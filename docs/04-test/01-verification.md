## 검증 전략

CI는 백엔드·SQL·프론트엔드 자동 테스트를 실행하며([README 테스트](../../README.md#테스트)), 카메라·OS 제어는 장비에서 별도 확인한다.

| 대상 | 확인 항목 |
| --- | --- |
| 아키텍처 | 내부 계층의 프레임워크/어댑터 import 금지, 모듈 간 공개 API 경계, 순수 도메인·가짜 포트 검증 |
| API·SQL | 미정의 영상 필드 거부, `frame_stored=0`, 이미지/BLOB 컬럼 부재, 모션 특징 저장 계약 |
| 학습·실행 | 승인 전 실행 금지, 맥락 분기, 활성 창 차단, 임계값·피드백 규칙 |
| 초기화 | 7개 종속 테이블 삭제 건수, 타 사용자 보존, commit 실패 롤백, 초기화 후 3회 학습·재제안 |
| UI | 3초 갱신·요청 병합, 편집·입력 보존, 오류 복구, 외부 학습 진행률, 실행 결과·닫기·피드백, dialog 비차단, Reset 복구, 직접 링크·히스토리, 모바일 메뉴·가로 넘침, 활동 동기화·동시 입력 방지·반복 학습 |
| 카메라 | 방향·특징·payload·맥락·키 연결, 실패 시 자원 해제, 정지 제외, 손바닥 재무장, 원형 궤적 |

## 화면 검증

기본 뷰포트(브라우저 UI 제외): 데스크톱 `1920×1080`, 모바일 `360×784` CSS px. 레이아웃·히스토리·입력 보존은 [검증 전략](#검증-전략), 카메라·OS 조작은 [실제 장비 검증](#실제-장비-검증)을 따른다.

## UX 흐름 회귀 검증

- 프론트엔드 테스트: 단계별 카드 노출(행동 연결·학습 제안·확인 몸짓), 빈 기억·맥락 학습 링크, 승인·거절 후 안내, 연결 재시도 시 bootstrap 복구.
- 브라우저 점검: 몸짓 → 행동 연결 3회 → 제안 승인 → 시뮬레이션 실행 → 피드백, 포커스 이동, 접힌 카메라 상태·펼침·중지 접근.

## 실제 장비 검증

- Python·브라우저 카메라 4개 몸짓 인식(성공·오탐·미탐) 및 장치 전환·중지·종료 시 `MediaStream` 해제 확인.
- 네트워크 캡처로 이미지·원본 프레임 전송 `0건` 실측(정책 API·문구로 대체 불가).
- Windows 실제 키 관측 → 제안 → 승인 → 재인식 E2E 및 대상 PC의 OS 실행 권한·활성 창·키 매핑 확인.
- 장비·OS·브라우저와 결과를 함께 기록하고 미수행 항목은 미확인으로 남긴다.

## API 계약 검증

API 변경 시 [REST API 명세](../03-tech/api.md)의 정상·거부·오류·상태/헤더를 검사하고 OpenAPI·라우터·DTO를 대조한다.
